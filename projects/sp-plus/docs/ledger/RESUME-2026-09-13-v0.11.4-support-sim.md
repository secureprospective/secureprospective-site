## 3. THE DEFECT (the real value of tonight)
`spplus-update-control status` reported **"This computer is up to date"** on the Dell
while 0.11.4 was published and reachable. `status` reads local state only and answered
from bootc's `cachedUpdate`; an ABSENT cached answer was reported as currency.

Verified against bootc 1.16.10 source (Bee) and measured on the VM:
- `cachedUpdate` is written by `ImageImporter::prepare()` — reached by
  `bootc upgrade --check` AND by a normal `bootc upgrade`. NOT by `--check` alone.
- `bootc status` NEVER refreshes it.
- It is ABSENT even after a successful check on a machine that is current — so an
  empty cache cannot distinguish "asked, and current" from "never asked".
- It PERSISTS across reboot (detached metadata on the deployment commit).
- `bootc upgrade --check` exits 0 whether or not an update exists.

**Fix:** a stamp at `/var/lib/sp-plus/last-check`, written only after bootc answers.
`status` returns a fourth state **`unknown`** when there is no fresh check behind it.
`stage` now runs its own `--check` instead of trusting whatever was cached.
`tests/update-lane-gate.sh` asserts the WIRING; wired into the Containerfile; fails
four assertions against the pre-fix file from git; carries its own mutation case.
