## Mutation tests

Three, all red before green.

1. **Build-time setuid gate.** One path removed from the allowlist. Build failed and named
   exactly that path.
2. **Runtime gate against the pre-Tier-1 install.** 18 failures, every Tier 1 assertion red with
   its measured value printed.
3. **Runtime gate against the Tier 1 install with six controls broken live.** Six failures, one
   per broken control, nothing else moved.

## Three gate defects the mutations found

These are the reason mutation testing is the rule and not a formality. All three were gate bugs,
none was a product defect, and two of them were producing a **green** result on a broken machine.

1. **The build-time setuid gate walked the ostree object store.** `find / -xdev` inside the build
   container reached `/sysroot/ostree/repo/objects/`, which holds hardlinked copies of the same
   binaries under content-addressed names. It reported the 22 allowlisted files a second time and
   failed the build. Fixed by pruning `/sysroot` and `/ostree`.

2. **The runtime setuid scan could not see the writable part of the machine.** A booted SP+ machine
   is composefs at `/` with writable xfs at `/etc`, `/var` and `/var/home`. A single `find / -xdev`
   stops at `/var`. A setuid binary planted in `/usr/local/bin`, which is `/var/usrlocal`, left the
   gate green. Fixed by naming every writable mount and pruning only the container and flatpak
   stores, which legitimately hold other images' setuid files. **This was the dangerous one:**
   `/var` is exactly where anything written after install would land.

3. **Several hardening sysctls are mode 0600.** An unprivileged `cat` returned nothing, and the
   gate reported `net.core.bpf_jit_harden` absent on a machine where it was set to 2. Fixed by
   reading through `sysctl`.

## Decisions carried

- **D46 holds.** Every control here has a posture-gate assertion.
- **D47 still unratified.** sshd ships disabled. It is enforced at build time only, because the QA
  kickstart re-enables sshd so the gate can connect at all. A runtime assertion in this lane would
  measure the harness, not the image.
- `kernel.yama.ptrace_scope` is **1, not 2 or 3.** Chromium and Brave ptrace their own child
  processes. This is the day-one rule deciding a security parameter, and it is the right call.
- `MemoryDenyWriteExecute` and `PrivateUsers` are deliberately absent from `sp-plus.service`.
  CPython does not need write-plus-execute but a C extension might, and that failure would be a
  runtime crash rather than a build error.

## Honest limits

1. Four new sysctl assertions already passed before Tier 1, because restricted dmesg, the two
   protected link controls and disabled unprivileged userfaultfd are Fedora defaults. They guard
   against regression. They are not evidence of anything this change made, and should not be
   counted as such in the Security Evidence Report.
2. Removing the two guest agents is untested on real hardware.
3. Suspend and resume have never been tested in this lane, under any phase.
4. The signature policy gate's tenth assertion still fails. That is the published image signature
   format, and it awaits a decision, not a fix.
