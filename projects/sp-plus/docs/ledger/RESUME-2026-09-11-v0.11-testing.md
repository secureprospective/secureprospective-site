## 6. HYPOTHESES REFUTED / TRAPS — DO NOT RETEST

### 6.1 The PAM design is DEAD (carried forward, still true)
sudo 1.9.17p2, the version SP+ ships: a matching `NOPASSWD` tag sets
`def_authenticate = false` and `check_user()` skips the branch containing
`pam_authenticate()`. A helper in sudo's `auth` stack never runs.

### 6.2 "A click proves physical presence" is NOT defensible (carried forward)
Five source-level routes: KWin `fake_input` (whose handler carries a literal
`// TODO: make secure`), portal preauthorization, XWayland XTEST via libei,
KWin EIS D-Bus, AT-SPI `DoAction`. `XwaylandEisNoPrompt` upstream default is
**false** — do not claim otherwise. This is why nothing claims to prove presence.

### 6.3 Publishing traps found the hard way THIS window
- **Neither podman nor skopeo had a ghcr credential**, and they use SEPARATE
  stores. Rootful podman pushes the image; skopeo (running as chris) signs it.
  Both were authenticated from the existing `gh` login, which carries
  `write:packages`. `publish-image.sh` checks for the key and for sigstore
  attachments but **never checks that it can authenticate**.
- **`publish-image.sh` pushes `:latest` BEFORE it signs.** A failure in between
  leaves the fleet on an unsigned image. Not hypothetical: the signing step failed
  on the real run. Recorded in the ledger as a recommended fix that is NOT made.
- **`podman push` refuses once local storage holds a signature** for that image:
  `Copying this image would require changing layer representation, which we cannot
  do: "Would invalidate signatures"`. A verification pull causes this.
  `:latest` was therefore moved with a digest-preserving `skopeo copy`.
- **DO NOT delete the `:signtest` tag.** On GHCR a package version is addressed by
  digest and holds all of its tags, so deleting that tag risks removing the
  manifest `:latest` depends on. It is harmless; nothing pulls it.

### 6.4 The absence-check trap, hit again
`grep -c "removes a prompt, not a boundary"` against the shipped sudoers returns
**1**, which looks like the correction failed. It did not: the phrase survives only
inside the sentence that refutes it, at line 32. Check the context, not the count.
This is the same class as `lesson_absence_checks_match_own_comments`.

### 6.5 Earlier in this session (carried forward)
- The registries.d lookaside is **NOT** missing from the image; an early `head -12`

- `ostree-unverified-registry:` on an installed machine is **NOT a defect**. It is

## 10. RELAY / ENVIRONMENT NOTES

- **Beelink `sudo` permits `podman` ONLY.** To delete a root-owned path, run
  `sudo -n podman run --rm -v <dir>:/w alpine sh -c 'rm -rf /w/<thing>'`. That is
  how `build-iso.sh` clears its own output and how `/var/tmp/spverify` was removed.
- Commit messages: write to a file and `git commit -F`. Inline heredocs through ssh
  break on apostrophes.
- Patch scripts: scp a file and run it. **Never nest heredocs through ssh.** Every
  patch must assert its target was found.
- Launching a long build: `nohup setsid bash -c '...; echo $? > sentinel'` and then
  poll the sentinel over a FRESH ssh each time. A single long-lived ssh holding the
  channel will hang the calling tool.

  `scp -i /root/.ssh/beelink /root/paste.md chris@192.168.1.190:/home/chris/Downloads/paste.md`.
