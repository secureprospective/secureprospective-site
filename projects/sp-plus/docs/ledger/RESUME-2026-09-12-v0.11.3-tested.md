## 3. HOW TO RECOVER A KILLED DISPATCH (built and proven this window — reuse it)
`bee-desktop` was killed with 0 bytes of stdout and its hour of work was fully recovered
from the session transcript. The method, because it will be needed again:

1. Transcript is `~/.pi/agent/sessions/<ts>_<session-id>.jsonl`. It is HUGE (35 MB) because
   every screenshot is base64 inline. **Never read it directly — it will eat the context.**
2. Parse it SERVER-SIDE with a scp'd python script. Message records are
   `{"type":"message","message":{"role","content":[...]}}`; content block types are
   `text`, `toolCall`, `thinking`, `image`.
3. **Pi stores `thinking` as SUMMARISED HEADERS, not full reasoning.** 125 thinking blocks
   rendered to 5.3 KB of bold one-line headers. You recover *what it looked at and what it
   concluded existed*, never the detailed argument. Plan for leads, not findings.
4. The surviving narrative of that run is kept at `beelink:/tmp/desktop-thinking.txt` (5303 B).

## 5. DEFECTS FIXED THIS WINDOW — commit `3fa1a3c`, pushed
1. **The advisor's menu favourites never reached the menu.**
   Root cause, and it is subtle: the layout's `favorites=` key is a **MIGRATION SEED**, not
   the store. Kickoff reads it only while the KActivities model is empty:
   `if (!PortedToKAstats) { if (count < 1) portOldFavorites(favorites); PortedToKAstats = true; }`
   Plasma ports its OWN stock defaults first, so `count < 1` is already false and our list is
   skipped. The advisor got Konsole (hidden from All Applications one section above!),
   Discover, System Settings and Kontact (not even installed).
   **Fix:** seed the kactivitymanagerd SQLite DB in `/etc/skel` so the model is non-empty
   before first login. `config/seed-kickoff-favorites.py` seeds AND reads the DB back,
   comparing it to `spplusMenuFavorites` in the layout, before it will exit 0.
   Mutation-checked 3 ways (lists disagree / list missing / layout file absent).
   **The taskbar was never affected** — `icontasks launchers` is durable config — and is unchanged.
2. **The partition editor cached its password.** kpmcore was ALREADY `auth_admin_keep` and the
   menu entry ALREADY hidden; the real flaw was `_keep` letting one password cover a whole
   session. `config/48-sp-plus-partition.rules` returns AUTH_ADMIN. The gate rejects the
   literal string `AUTH_ADMIN_KEEP` — a plain grep for AUTH_ADMIN would match the very thing
   being removed.

## 7. ARK — FULLY CHARACTERISED, fix identified but NOT shipped
**Ark creates archives that Ark then refuses to open.** It names entries by their path
*relative to cwd*; if the file is not under cwd that name starts with `../`. Ark writes such an
archive happily (`add rc=0`) and its own anti-Zip-Slip guard then rejects it.

Reproduced, same file, only cwd differs:
| cwd | entry stored | extract |
|---|---|---|
| the file's own folder | `notes.txt` | rc=0, recovered |
| an unrelated deep folder | `../../../../../home/test/Documents/notes.txt` | **rc=124 hung, nothing extracted** |

Journal: `Possibly malicious archive. Detected entry that could lead to a directory traversal attack`.
It **hangs** rather than failing cleanly (the "Application closed unexpectedly" notification), and
discards safe sibling entries too — a control `innocent.txt` was lost, while plain `unzip`
sanitises the path and extracts both. Security is fine: the real file was never touched.

**The fix exists in Ark: `-p/--changetofirstpath`.** Same failing command with `-p` →
entry `notes.txt`, extract rc=0. Shipped `org.kde.ark.desktop` is `Exec=ark %U`, no `-p`.
**NOT shipped, deliberately:** `-p` makes entries relative to the FIRST entry, so a multi-file
selection spanning folders can reintroduce `../` for the others; and `%U` is also how Ark is
launched to OPEN an archive, where `-p`'s effect is untested. Needs a test matrix first.
Severity: Low/Medium — the common Dolphin path (cwd = the file's folder) works.

⚠️ **CLI trap:** there is no `--archive` flag. It is `-t/--add-to`. Two of my runs "failed"
purely because of that; the results in this section are from corrected commands.
