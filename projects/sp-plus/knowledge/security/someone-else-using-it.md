# When someone else uses this computer

**Do not hand someone an unlocked SP+ session as a blank computer.** It can show documents, email, browser sessions, File Portal windows, and client work.

## The safe default is no sharing

Do not give another person your desktop password, disk passphrase, recovery key, Bitwarden access, or multi-factor device. A screen lock is not a handoff. Someone at an unlocked session can act as you in its open services.

For a visitor, open only the non-sensitive item, stay present, and lock the computer when the conversation ends. Press **Meta+L** before stepping away. The Meta key has the Windows logo.

If the person needs to do ordinary work, use their own approved device when possible. A laptop with client work is not a general family, visitor, or office computer.

## An open website is already access

The verified Brave policy disables its built-in password saver and credit-card autofill. That reduces stored browser secrets, but it does not close an email, File Portal, CRM, meeting, social, or other website that is already signed in.

A private browser window does not create a separate SP+ user or make an active account safe to share. It is not a tested access-control plan. Close sensitive windows before anyone can see the screen, and use the account's own sign-out control when finished.

## A second person needs a deliberate setup

SP+ includes a **Users** component in System Settings and the standard account service. The checked virtual machine had one ordinary user, no configured automatic sign-in or guest session. Creating, deleting, or switching accounts was not tested as an SP+ workflow.

Do not create an account, turn on automatic sign-in, or rely on a guest setup because a web guide says it is convenient. Ask the person responsible for computer setup to decide whether the other person needs a separate approved device or account. That decision should cover access, passwords, data, backups, and what happens when they leave.

## If someone used it unexpectedly

Lock the screen, note when it happened and what they may have seen, then follow your practice's incident process. If an account may have been open, review its sessions and controls from a trusted device.

Do not delete files, browser history, or messages to make the event disappear. That can remove evidence without proving access ended. Do not give Fin client information, a password, or screenshot while asking what to do.

## What separate access does not solve

A separate account or device does not make shared folders, emails, portals, cloud services, printers, or screen shares private by itself. Decide who receives each file or message. Disk encryption helps only when the computer is powered off and locked; it does not stop someone using an unlocked session.

## A short handoff checklist

1. Close client files and signed-in sites you do not need.
2. Press **Meta+L** before leaving the computer.
3. Do not share your password or security codes.
4. Use a separate approved device or account for ongoing access.
5. If access was unplanned, record it and follow the practice's incident process.
