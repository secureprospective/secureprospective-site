## Public API (types only)

```ts
// Agent identity / advertisement
interface AgentCard {
  name: string;
  description: string;
  url: string;
  provider?: { organization: string; url?: string };
  version: string;
  capabilities: AgentCapabilities;
  skills: AgentSkill[];
  defaultInputModes?: string[];
  defaultOutputModes?: string[];
}

// Unit of work between agents
type TaskState = "submitted" | "working" | "input-required" | "completed" | "canceled" | "failed";
interface Task { id, sessionId?, status, messages?, artifacts? }

// Communication within a task
type MessageRole = "user" | "agent";
interface Message { role, parts: MessagePart[], messageId?, taskId?, timestamp? }
type MessagePart = TextPart | FilePart | DataPart;

// Outputs produced by a task
interface Artifact { artifactId, name?, description?, parts: MessagePart[], index? }

// Protocol envelope (JSON-RPC 2.0)
interface A2ARequest { jsonrpc, method: A2ARequestMethod, params, id? }
interface A2AResponse<T> { jsonrpc, result?, error?, id? }
const A2A_ERROR_CODES: { PARSE_ERROR, INVALID_REQUEST, METHOD_NOT_FOUND, … }
```

## Decisions made

1. **Types only, no transport, no consumer.** §5.4 was explicit. Even a "demo" `Agent` constructor that consumes these types would be over-building per §8 ("P3 dark stubs should take a fraction of the effort P0 gets").
2. **Types match the public A2A spec surface (`github.com/a2aproject/A2A`).** When Year-2 A2A work begins, this is the seed; the type names align with the spec so a future implementer doesn't have to rename.
3. **No LEADS raised.** No dep decision, no API surface, no security gate. The component is fully inert.

## Hand-off to CT105

## LOW-CONFIDENCE ITEMS

The A2A spec is evolving (Google announced it but adoption is early). The types above mirror the public spec as of mid-2026; verify they still match before any Year-2 implementation work begins. The risk is low because nothing consumes these types today.
